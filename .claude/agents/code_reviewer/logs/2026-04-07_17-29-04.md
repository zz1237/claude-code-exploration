## Summary

Both scripts are well-structured and functional for their respective purposes:

- **convert_to_parquet.py**: Converts CSV files from a source directory to Parquet format with proper error handling and logging.
- **visualize.py**: Generates KPI calculations and creates six distinct visualizations from migrated Parquet data.

While the code is generally clean and readable, there are several critical issues related to path handling, error resilience, hardcoded assumptions, and code organization that should be addressed before production use.

## Critical Issues

### 1. **Path Separator Inconsistency (CRITICAL - convert_to_parquet.py)**
**Location:** Lines 92-93  
**Severity:** CRITICAL

```python
source_base = r".\.claude\skills\fetchAPI\data"
output_base = r".\.claude\skills\migrate\data"
```

**Issue:** Uses Windows backslash separators (`\.`), which will fail on Unix/Linux systems. This violates cross-platform compatibility.

**Risk:** Script is not portable to macOS, Linux, or cloud environments.

**Recommendation:** Use `Path` objects with forward slashes or `os.path.join()`:
```python
from pathlib import Path
source_base = Path(".") / ".claude" / "skills" / "fetchAPI" / "data"
output_base = Path(".") / ".claude" / "skills" / "migrate" / "data"
```

### 4. **No Handling of Missing Required Columns (CRITICAL - visualize.py)**
**Location:** Lines 54-57, throughout the script  
**Severity:** CRITICAL

```python
fact_sales = pd.read_parquet(DATA_DIR / "fact_sales.parquet")
fact_returns = pd.read_parquet(DATA_DIR / "fact_returns.parquet")
dim_store = pd.read_parquet(DATA_DIR / "dim_store.parquet")
dim_product = pd.read_parquet(DATA_DIR / "dim_product.parquet")
```

**Issue:** No validation that files exist or contain expected columns. If files are missing or have schema mismatches, the script crashes at runtime without helpful context.

**Examples:**
- Lines 68, 72: Assume `net_amount` and `refund_amount` columns exist
- Lines 80, 84: Assume `store_sk`, `product_sk` exist
- Line 168: Assumes `return_reason` column exists

**Risk:** Production failures with unhelpful stack traces. Data integrity issues go undetected.

**Recommendation:** Add validation function:
```python
def validate_dataframe(df: pd.DataFrame, required_columns: list, filename: str) -> None:
    missing = set(required_columns) - set(df.columns)
    if missing:
        raise ValueError(f"{filename} missing columns: {missing}")
```

Always validate DataFrames have expected columns before operations:
```python
def require_columns(df: pd.DataFrame, *cols: str) -> pd.DataFrame:
    missing = set(cols) - set(df.columns)
    if missing:
        raise ValueError(f"Missing: {missing}")
    return df
```
